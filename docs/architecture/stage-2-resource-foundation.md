# Stage 2: document pixel-budget foundation

Status: **in progress; not the complete shared-memory manager or atomic-stroke implementation**. This increment introduces a per-document shared accounting object for layer tile pixel buffers and temporary `restoreTiles` copies. It does not change the `.koma` format, brush rasterization, history representation or public undo interface.

## What is covered

Each `LayerModel` owns a shared `DocumentMemoryBudget`; its initial and newly created layers attach the same object before allocation. Individual document instances do not share it. `SparseTileStore` reserves a tile's pixel bytes before allocating it, releases reservations on rejected capture, dirty-tracking or allocation failures, and releases them on tile reclamation and destruction. `restoreTiles` reserves all incoming pixel-copy staging before allocating, keeps original tiles charged until commit, converts the staging reservation to artwork after commit, and releases it on validation/allocation failures. Original artwork and accounting remain unchanged if staging fails. Deleted layers release their pixel charges. Budget changes below current use are rejected.

The shared object exposes artwork, staging, current and high-water bytes to C++ callers. Standalone stores remain usable without a document budget. Both the object and stores are restricted to the document thread; they are not an allocator or process memory meter. At this foundation stage tile pixel buffers were charged using the logical full-tile byte size; later increments added partial history and composite-cache charges as described below. Container capacity, allocator/Qt overhead and temporary file buffers remain excluded. `restoreTiles` may reject an operation whose final pixel size fits when insufficient headroom exists to stage it; that is intentional for its atomic restore guarantee. Current undo/redo still allocates and can fail safely without changing its cursor.

## Transition and limitations

To avoid introducing an arbitrary new ceiling or breaking existing workflows before the complete accounting and settings exist, the document budget is initially **unlimited** (`size_t` maximum). Existing 256 MiB per-layer and 64 MiB history safeguards remain active. Tests explicitly configure small shared limits to exercise cross-layer enforcement. This does **not** enforce a comprehensive document-wide limit in the application and does not deliver effectively unrestricted history. A process-level coordinator, realistic OS-aware limits and preferences, history/cache/temporary accounting, and an emergency replay reserve are still required. The subsequent transaction increment below adds rollback; its untested boundaries still prevent a blanket atomicity claim.

The new `DocumentMemoryLimit` failure distinguishes a shared pixel-budget refusal from a per-layer limit. Currently the user-facing message identifies the category; it does not claim total process memory is exhausted. Preservation of existing New Project, brush, undo and file workflows is a release gate for every increment.

## Transaction increment

Recorded brush strokes now retain emptied tile nodes until commit or rollback. `UndoStack` captures the before image and reserves the after image before each tile's first write. On a failed write or cancelled stroke, it restores captured pixels in existing tile buffers, removes newly created tiles, and preserves the history cursor/redo branch without allocating C++ memory in the tested rollback path. The viewport invalidates its composite cache after rollback and restores the pre-stroke modified flag; saving is rejected while a stroke is in progress. A failed stroke is no longer intentionally committed as partial paint. The existing 64 MiB history cap and 256 MiB per-layer cap remain.

The shared document counter additionally includes **logical pixel-buffer bytes** reserved by history commands (including the in-progress stroke) and retained composite QImage cache payload. History reservations for unchanged snapshots are released when those snapshots are removed at commit; retained snapshots remain charged until their command is destroyed. Cache accounting does not include transient images or copies retained elsewhere; cache insertion falls back to an uncached composite when the shared budget cannot accept it. These counters are not the same as process memory. The application still does not set a finite document-wide policy by default.

Tests exercise history-limit and shared-budget refusal after earlier modifications, exact semi-transparent pixel restoration, tile creation/reclamation, redo preservation, cache cleanup and C++ allocation failure at stroke start and across a subsequent tile write. An isolated test arms the C++ allocation failure injector during rollback and successful command commit. This is evidence for those paths, **not proof that every transaction boundary or every Qt/OS allocation has been fault-injected**. Remaining work includes broader UI/event and concurrency failure coverage, potential failures in Qt notifications and platform allocation, document-wide accounting for object/container/allocator overhead, dirty tracking, viewport frames, temporary composite and file I/O buffers, and a process-level coordinator. Undo/redo still stages replacements through allocating `restoreTiles` and may fail safely under memory pressure; no reserved replay workspace, adaptive history or disk tier exists yet. Existing layer deletion and redo-branch behavior have not been redesigned.

## Undo/redo preparation increment

`SparseTileStore::restoreTiles` reserves the total incoming tile-pixel staging charge, prepares replacement tile buffers, stages dirty-region changes, and reserves map capacity before changing artwork. Failure in these steps leaves artwork, dirty regions and history cursor intact; successful preparation commits replacements before notifying consumers. Undo and redo now reject reentrant history mutations during replay. Dirty-tracker allocation failure is reported as allocation failure rather than as a tracking limit. This does **not** establish a permanently allocated replay reserve: a future undo may be refused safely under memory pressure and can be retried when resources are available.

Added tests inject C++ allocation failures at successive positions during real `UndoStack` undo and redo, twice each on the same history followed by an unrestricted successful retry. They check full tile pixels, semi-transparent values, tile creation/removal, dirty regions/versions, shared-budget totals and the unaffected second layer. Each current stroke command targets **one layer**, so the tests cover successive commands on different layers, not an unsupported single command spanning multiple layers. Separate tests exhaust the shared staging budget, retry, and attempt reentrant undo/redo/clear/start from layer notifications.

Accounting coverage must not be overstated:

* **Fully tracked logical reservations:** tile pixel payload and replay pixel staging reservations are acquired and released through the document budget; the reservation counters are checked by tests. These are logical byte charges, not a complete allocator-level census.
* **Partially tracked:** history pixel buffers and retained composite QImage payload are charged, conservatively in some cases. Actual vector capacities, QImage sharing/lifetimes, command metadata, allocator overhead and temporary composition copies are not fully attributed. The application still has no active overall finite document budget by default.
* **Not tracked:** dirty-map/hash-table nodes and rehashing, temporary metadata, Qt signal/slot allocations, viewport frame and GPU resources, file I/O buffers, application/runtime allocations and platform memory. Replay does allocate/prepare metadata before artwork mutation, but those bytes are not budgeted. There is no process-wide coordinator or persistent replay workspace.

Failure injection overrides C++ `operator new` in an isolated test process; it does not cover all Qt allocation mechanisms, OS failures, signal callback reentrancy such as external layer destruction, or concurrent/background edits. Multi-layer atomic commands are not implemented. Full UI, hardware and long-session performance verification also remain outstanding. Stage 2 remains incomplete.

## Replay deletion and allocation-lifetime audit

Replay now asks the tile store to commit without callbacks, advances the cursor, and then emits tile notifications while holding a guarded layer pointer. If a synchronous listener removes the replayed layer, notification stops before touching it again. A command whose layer is already missing is refused with an error and retained rather than cleared. Tests delete a model-owned layer on the first notification of a two-tile undo and redo, verify the other layer and budget, and retry the now-inaccessible command. This does not prevent a listener from destroying the history object or document itself, nor prove safety for layer deletion during ordinary stroke/write/batch callbacks. Outside replay, the existing workspace layer-deletion handler explicitly clears history and reports that to the user; layer deletion is not an undoable layer-state command. A multi-layer atomic command is not implemented and cannot be tested as if it existed.

The replay rejection tests compare dirty maps and versions. The later dirty-state increment below snapshots and restores the pre-stroke dirty map/version in the tested paths; cache invalidation is still needed for frames rendered during the stroke. Existing tests also do not exhaustively inject at all Qt/OS allocation or signal/commit boundaries.

Allocation inventory (document thread, logical charges rather than allocator/process bytes):

| Category | Coverage and boundary |
|---|---|
| Layer tile pixels and staged replay copies | Fully tracked **logical full-tile** reservations on attached stores, including staged overlap; vector capacity/allocator overhead are not measured. Standalone stores may be unattached. |
| Undo before/after pixels | Partial: logical pixel reservation; unchanged snapshot charges are released at commit. Vector capacity, commands, metadata and temporary allocations are not charged. |
| Retained viewport composite QImages | Partial: cache payload charge only; QImage sharing, metadata, other references and transient composites not fully accounted. |
| Layer/model/document objects, names and Qt collections | Untracked. |
| Tile hash nodes/buckets, dirty-region maps, replay staging containers and vector capacity | Untracked; some are allocated before mutation but not reserved in the shared budget. |
| Brush scratch, compositor output/plans, viewport frame, GPU/driver resources | Untracked. |
| File parsing, validation, serialization and save/open temporary buffers | Untracked. |
| Qt events/signals, allocator overhead, stacks and OS/runtime resources | Untracked; process-wide memory coordination is absent. |

Lifetime tests exercise tile reclamation and recreation, command destruction before layer destruction, retained history charges, zero staging after replay, and final release to zero. A document-replacement test also checks that history charges are released on replacement and old artwork charges on destruction, independently of the replacement document. These are not a full proof of replacement with every cache or callback, cache sharing, allocator rounding, or every error path. The default document budget remains unlimited and the existing per-layer safeguard remains. Peak logical reservation is available but is not peak process memory; the earlier Windows headless process-memory baseline does not measure this replay increment's peak or responsiveness.

## Dirty rollback and callback-lifetime increment

A recorded stroke copies its dirty tracker before any pixels are changed. A failed snapshot refuses to start the stroke. Cancel or rejected commit restores the saved map and version by move without allocating C++ memory; the viewport still invalidates its composite cache because it may have rendered intermediate pixels. Allocation-failure and history-limit tests cover a partial erase followed by a rejected second tile, dirty regions/version, alpha, tile existence and preserved redo. This is evidence for these scenarios, not every possible failure mechanism. The snapshot's map allocation and metadata remain untracked by the document budget. Restoring a version can reuse an earlier number: current viewport invalidation discards its synchronous plan on rollback, but stale externally retained plans and asynchronous consumers are not verified.

Replay now checks a guarded history pointer after each notification as well as the layer pointer; tests delete history, layer or document synchronously during replay. A model-level layer removal is refused during a store's synchronous change notification, and stroke commit/cancel/clear cannot reenter during that notification; direct and batched callback tests cover those cases. These protections do not cover arbitrary direct deletion of a layer/document/viewport/history during an active brush or store callback, nor all document-replacement and Qt event callbacks. The model still explicitly clears history with an error on ordinary layer deletion; deleting a document is not undoable. No general lifetime guarantee is claimed.

There is no fixed stroke or undo-step count, but the current 64 MiB history byte limit and whole-tile before/after representation can reject painting after relatively few small strokes. Painting and history capacity are not yet independent in the product sense: a stroke requires history space and fails safely when it is exhausted. The budget is only C++-configurable, defaults to unlimited, and is not a sensible user-configurable document-wide policy. It excludes significant metadata, temporaries and platform memory. A finite default or user preference is not introduced here without a validated accounting/policy; this remains essential work, as do efficient small-change history, eventual disk storage, and recovery without silent history loss. Existing per-layer safeguards remain. Do not describe Stage 2 as complete.

The Windows smoke now extracts and runs the actual ZIP with a system-only PATH plus the extracted application directory, and removes Qt plugin/QML search path overrides. The five-second native-window assertion is unchanged. Passing this isolates the package from the installed Qt SDK on PATH, not from every possible Windows system dependency, and does not diagnose intermittent startup on its own.
