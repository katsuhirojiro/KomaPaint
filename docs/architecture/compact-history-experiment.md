# Compact history codec and production integration

Status: **integrated into in-memory brush undo/redo, not `.koma` or disk history**. The current 64 MiB safeguard has not been removed. The existing document budget defaults to unlimited and does not fully account for process memory; removing the cap before a controlled resource policy and safe retained-record admission are in place would permit uncontrolled growth. This is unfinished product work, not the requested replacement.

## Limit audit

* `src/history/UndoStack.h`: `m_limit` defaults to 64 MiB; `byteLimit()` and `setByteLimit()` expose the current limit (the setter requires an empty history).
* `src/history/UndoStack.cpp`: `captureTile` enforces the limit using `2 * tileBytes + 512` per touched tile; `m_bytes` and `m_currentBytes` maintain conservative charges. It reserves before painting, and a failed recorded stroke rolls back. Redo remains charged until an explicit branch-changing commit or clear.
* `src/canvas/SparseTileStore.h/.cpp`: `CaptureResult::Limit`, `WriteResult::HistoryLimit` propagate failure; a poisoned recorded stroke also returns `HistoryLimit` on subsequent writes. These represent failures rather than another 64 MiB definition.
* `src/app/CanvasViewport.cpp`: turns `HistoryLimit` into a user-facing message and shows `byteLimit()`; must change when resource policy changes.
* `tests/unit/TestHistoryAudit.cpp`: measures a forced full-snapshot fallback for 127 strokes and compares a 10,000-stroke compact workload; the older pre-integration test documented rejection of stroke 128. `TestUndoStack.cpp` and `TestCanvasViewport.cpp` use deliberately small `setByteLimit` values to exercise rollback; `TestTileAllocationFailure.cpp` checks propagation of a rejected capture. Preserve equivalent exhaustion and rollback tests when replacing the limit.
* Current descriptions: `docs/architecture/artwork-history.md`, `stage-2-resource-foundation.md` and `painting-resource-audit.md`. `undo-resource-design.md` records the approved replacement plan and treats 64 MiB as a historical bottleneck. This audit's measurements are historical, not a claim about a future implementation.

## Codec

`src/history/HistoryTileCodec` encodes one pair of equally sized tile states, with an explicit existence flag for each. It computes the exact candidate payload size first, then selects the smallest of: changed pixel indexes plus old/new 32-bit values; run-length encoded before/after snapshots; or raw before/after snapshots. Integers in its payload are little-endian, but the surrounding in-memory record is **not** a stable disk format. The RLE option is a lossless compressed tile snapshot; it is deliberately simple and is not a general-purpose compressor. Raw fallback prevents compression expansion. Apply reconstructs either direction and checks the input tile and payload shape. No layer identity, command ordering, durable index, checksum, spill, recovery, or disk quota is implemented.

`test_history_tile_codec` checks sparse, dense and incompressible candidates; exact 32-bit pixel values and alpha; absent-to-present and present-to-absent tiles; 300 deterministic randomized round trips; corrupt input; injected C++ allocation failures without mutating source pixels, and a textured semitransparent real brush across three tiles with reverse/forward restoration through the tile store and a second layer left unchanged. It also measures 10,000 copied one-pixel records: allocated payload capacity and record-vector capacity separately, plus real process memory, encoding and forward-decoding time where the platform supports them. The measurement includes process/runtime effects and the earlier tests in the same process; it is not a painting latency benchmark, and payload/vector capacities exclude allocator headers and other allocations. Results are emitted as CI annotations. The standalone codec test does not itself cover `UndoStack`; production history and failure tests cover the integrated path. Multi-layer atomic commands are not implemented.

## Production transaction and accounting

`UndoStack` still reserves full before/after tile buffers and the legacy conservative charge before painting. After `finishCapture`, it temporarily reserves space for both raw and compact representations and encodes each tile while retaining the full fallback. Only once all records exist and are smaller does it replace the raw buffers and charge their actual vector capacities (plus a conservative per-tile allowance in the history safeguard). Allocation, budget or encoding failure leaves the admitted full snapshots intact and commits that fallback; no redo entries are removed until the record is ready. Unchanged tiles are discarded as before. Undo/redo reserves decode staging, reconstructs every tile before calling the existing atomic `restoreTiles`, and advances the cursor only after success. Invalid input, allocation failure or budget refusal leaves artwork and history unchanged. The full snapshot fallback remains replayable and has been deliberately exercised by the tests.

The shared budget tracks the compact vector and payload capacity, and a conservative logical pixel upper bound during encoding and replay; it does not include all allocator rounding, history command/index metadata, dirty-map copies, signal/Qt allocations, or process memory. Actual peak temporarily includes raw plus encoded copies and replay decode plus store staging. The application-wide document budget remains unlimited by default. The 64 MiB safeguard remains (and can still refuse a stroke); no finite safe replacement or disk storage exists. This is an integration increment, not completed Stage 2 or the requested final policy. Delta replay verifies changed pixels and preserves other pixels, while compressed/raw snapshot replay verifies the entire source tile; unrecorded external mutation can therefore make replay refuse rather than overwrite unexpected artwork.

## Gates before replacing the safeguard

1. Expand transaction fault injection and actual-allocation accounting beyond the tested C++ failure points, including Qt/OS failures and callback lifetime boundaries. Verify the full fallback and replay workspace under sustained pressure.
2. Replace the fixed cap with a genuinely controlled, OS-aware/configurable resource policy that accounts for actual retained records, transient buffers and overhead, with a safe exhaustion path. Keep existing layer safeguards and never silently prune history. A policy/preference UI must describe behavior that actually exists.
3. Add a stable versioned record/storage interface, checksums and a bounded disk tier with safe write, read, disk-full and recovery handling before claiming disk-backed history. No current prototype bytes are persisted.
4. Differentially test real strokes and pixel-identical undo/redo on multiple tiles/layers; test cancellation, allocation failures, repeated recovery, redo, dirty state and lifetimes. Measure peak real process memory and operation latency over long sessions and manually test the Windows build.
